# Small-model pilot: Haiku and GPT Luna, with and without codenav (2026-11-27)

srxy-ab at 953d27c, codenav v2 at dd9da03. Each run used its own clone. Both arms got the same task text as the
Sonnet A/B (COMMON block plus TASK N) and the same built-in tools; the codenav arm also had the 12 codenav tools.
Neither arm was told to use codenav.

- Haiku: `claude -p --model claude-haiku-5-5`, tools Read, Grep, Glob, Edit, Write, Bash.
- Luna: `codex exec -m gpt-6-luna`, reasoning effort medium, user config ignored, shell and apply_patch.
- Tasks: 1, 3, 4 and 5 from orchestrator-prompt.md; 8 and 9 from scripts/small-models/extra-tasks.md.
- 1 repeat each, 24 runs in total. **Treat each cell as an anecdote:** the arms of the same model differ by 30-50% in
  tokens even where codenav was never called.

## In plain words

- **On most tasks codenav made no difference to correctness.**
  - All 24 runs ended with ty clean and the tests passing.
  - In tasks 1 and 9 (8 runs, a read-only answer and a dead-code deletion), every run was right: the 3 real callers;
    deleting the dead cli.py copy and keeping search_runner's.
  - Only task 8 separated the runs, and only on files the tests don't cover: docs, examples and shell scripts.
  - srxy is small and its names are distinct, so grep plus the test suite is enough for a careful small model.
- **Haiku picks codenav up on its own; Luna doesn't.**
  - Haiku called codenav in 5 of 6 tasks: lookup, rename with a preview and then `edits apply sites=["all"]`,
    change_signature and impact.
  - Luna called it in 0 of 6, although the tools were loaded; a separate check had it call `outline` successfully.
  - Control run: GPT-6.1 Terra under the same `codex exec` setup (task 8, codenav arm) called `rename` and `edits`, and
    got examples/playground.py and docs/python-api.md via the opt-in sites. So the 0 of 6 is Luna's own behaviour,
    not Codex hiding the tools (one run; it lives in terra-control/).
  - So whether a model picks the tools up varies by model, not by size: small Haiku does, small Luna doesn't.
- **Where Haiku did use codenav on a big change, it worked with less effort.** Task 8 (rename a field across 35 files):
  - with codenav: 11 tool calls and 216k tokens in;
  - plain: 21 calls and 452k tokens in;
  - same correctness, apart from the gap below.
  - Over all 6 tasks the totals are about the same (1.41M against 1.39M in), because task 5 cost the codenav arm more
    even though it never called codenav there.
- **codenav made the answers more complete where it offered opt-in sites.**
  - In task 8, Haiku with codenav also fixed `examples/playground.py` and `docs/python-api.md`, which codenav offered
    as optional sites u1 and u4.
  - Luna missed `docs/python-api.md` in both arms and missed `examples/playground.py` in its codenav arm (where it
    didn't call codenav).
- **Gap found in codenav:** Python embedded in shell scripts isn't scanned.
  - `scripts/docs/export_gui_screenshot.sh` and `export_tui_screenshot.sh` build `FileSearchResult(lines=...)` in a
    Python heredoc.
  - Only plain Haiku, which grepped everything, renamed them. The codenav reply only counts other text mentions, and
    never looks at `.sh` files.
  - Those scripts aren't tested, so the miss shows up only when someone runs them.

## Limits

- 1 repeat, 1 repo, 6 tasks; the noise between arms is larger than most of the differences.
- Luna ran at medium effort only. Haiku ran at the CLI's default effort.
- Luna was not tried with a hint (for example an AGENTS.md line saying to prefer codenav for Python symbols); that is
  the obvious next arm.
- Tasks 3 and 4: running the API docs generator on those patches changes nothing, so "ok" there also covers the docs.
